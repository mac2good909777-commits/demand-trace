## 2026-09-22：🔴 `action=watch` 寫入端「靜默失效」——觀察名單分頁已 4 天沒進過任何新列

### 這次和前幾次不一樣：不是網路封鎖，是端點回報成功但沒寫進去

9/20、9/21 兩輪的問題是 `script.google.com` 被 egress proxy 擋掉（connect_rejected），
**那種失敗看得見**。本輪端點完全可連，**讀取（`?list=watch` / `?list=progress` / `?list=records`）
與事件寫入（records）全部正常**，唯獨 `action=watch`：

```
POST {"token":"muju-trace-2026","action":"watch","company":"福懋科技",...}
→ {"ok":true,"added":0}        ← 回報成功，但試算表沒有這一列
```

已用四種 payload 形狀交叉測試（英文鍵 `company`／中文鍵 `公司名稱`／
陣列 `watchlist:[...]`／陣列 `watch:[...]`／`name` 鍵），**全部回 `{"ok":true,"added":0}`，
全部沒寫進去**（測試列亦未殘留，試算表乾淨）。

**判定：`action=watch` 處理函式本身故障，不是呼叫端格式問題。**
`ok:true` 讓呼叫端誤以為成功，所以**過去幾輪都沒有人發現**——這是本次最該修的一件事。

> ⚠️ **教訓（要寫進排程流程）**：Apps Script 的 POST **失敗回應不代表沒寫入**。
> 本輪 404／HTML 中斷頁其實都已成功寫入，盲目重試就會產生重複列。
> **往後重試前必須先 `?list=records` 讀回確認該列是否已存在**，不可只看 POST 回應碼。

### 建議修法（下次有人動 Apps Script 時）

1. 修 `action=watch` 處理函式——目前回 `added:0` 且不拋錯，屬靜默失敗
2. 讓 `added:0` 在呼叫端視為**失敗**而非成功（本排程已於本輪起改為讀回驗證）
3. 事件寫入加上以「公司＋事件日期＋事件類型」為鍵的伺服器端去重，避免重試造成重複列
