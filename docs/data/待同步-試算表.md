## ⚠️ 本輪的一個方法論發現（值得固定下來）

C 線的過濾條件抓不到。

**結論：本任務自行掃描 MOPS 這一步不能省，也不能改成只讀 C 線的 MOPS 判讀。**
兩者的過濾邏輯不同——C 線看不動產關鍵字，本任務要看的是「設備／廠務工程」這類
**建廠進度指標**，它們往往不含不動產字眼，卻是最早期的需求訊號。

### 判斷

`records` 的 POST 正常、`watch` 的 POST 回 ok 卻 `added:0`，
代表**問題在 Apps Script 的 `action=watch` 分支本身**（可能是欄位比對或去重條件寫錯），

`{"ok":true}` 讓失敗變成靜默的——這是最需要修的一點。

1. 檢視 Apps Script `action=watch` 分支，找出為何 `added` 恆為 0
2. 讓失敗回 `ok:false` 或帶錯誤訊息，不要回 ok
3. 修好後把落後的 26 家一次補寫（來源以本機 `watchlist.json` 為準）
